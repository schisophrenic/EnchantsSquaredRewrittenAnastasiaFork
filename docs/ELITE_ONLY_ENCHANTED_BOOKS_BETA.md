# Enchanted books and randomized equipment (Purpur 26.3 beta)

## Rates

```yaml
elite_enchanted_books:
  enabled: true
  chance: 0.02                   # 2% per player-killed ValhallaEquipment elite
  require_player_kill: true
  chest_chance: 0.00002           # 0.002% per natural structure chest loot event
  fishing_chance: 0.00002         # 0.002% per successful catch
  equipment_enchant_chance: 0.20  # Existing chest gear / new random equipment
  elite_equipment_enchant_chance: 0.20
```

One roll per eligible event, not per enchantment candidate. Each eligible chest, catch or elite mob drops **zero or one enchanted book** from this listener. Level is randomly I through the selected enchantment's registered normal maximum.

The elite book check uses ValhallaEquipment's `valhallaequipment:elite_mob_v1` BYTE PDC tag. If ValhallaEquipment is absent or the mob lacks that tag, no elite book is generated.

## Other randomized rewards

- Natural loot chest equipment may receive one compatible random native/vanilla enchantment with a random level.
- ValhallaEquipment elite mob armor and held weapons may receive one enchantment per eligible piece when the mob spawns.
- Elite mob equipment drops may receive a compatible random enchantment.
- Equipment generated by EnchantsSquared's native low-quality loot may receive an enchantment.
- The gear enchant chances are **independent of the 0.002% book chances**.
- Lesser/Advanced/Supreme NG-gated enchantments are excluded from the random loot pool.
- Existing item PDC, ValhallaEquipment models, quality and random attributes are preserved.

## Boundaries

This changes book drops in EnchantsSquared's `LootGenerateEvent`, `PlayerFishEvent`, and `EntityDeathEvent` handlers. Existing inventory books, ordinary enchanting and villager trades remain available. Other plugins that spawn item entities independently of these events can still produce enchanted books. Books already held by players are not removed.

Vanilla enchanted books generated by a natural structure chest or fishing loot table are replaced by the controlled single-roll logic. That makes the configured rate apply to the full event rather than being added on top of vanilla book chances.

## Testing

1. Make a backup and use a staging Purpur 26.3 server.
2. Temporarily use `chest_chance: 1.0`, `fishing_chance: 1.0`, `chance: 1.0`. Open fresh natural structure chests, fish successfully, and kill `/valeq mobspawn ZOMBIE 30 true`.
3. Each successful source should produce **one** book, not two. The exact enchantment and level should vary.
4. With `equipment_enchant_chance: 1.0` and `elite_equipment_enchant_chance: 1.0`, test random chest equipment and armor/weapon on elite mobs. Check their original ValhallaEquipment PDC/model/lore survived.
5. Kill `/valeq mobspawn ZOMBIE 30 false` and confirm it gets no elite-book reward.
6. Restore the production defaults. `0.00002` is **one success on average in 50,000 events**, not one in 5,000 and not a guarantee.
7. If the beta build fails, inspect the workflow's Maven log artifact and compiler error. The workflow now uses `target/EnchantsSquared_2.7.jar`, which matches the Maven dist module's `../target` output directory.

No successful Maven build or live server test has yet been verified for this branch.
